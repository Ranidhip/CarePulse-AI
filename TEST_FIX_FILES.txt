ROOT CAUSE:

  make_user() in the test file hardcoded id="test-user-id" for every
  fake CurrentUser it built. But the fake provider_profiles row in
  _provider_fake_client() was seeded with
  user_id=PROVIDER_USER_ID ("provider-auth-user-1") — a different string.
  get_provider_profile_id() looks up provider_profiles by user_id, so it
  never found a match, and every one of these tests failed the
  provider-profile lookup before ever reaching the assignment check they
  were actually meant to test.

  This also means test_provider_cannot_access_unassigned_patient was a
  false positive: it asserted 404 and got 404, but for the wrong reason
  (missing provider profile, not missing assignment) — it would have
  passed even if has_active_assignment() were broken.

THE FIX:

  - make_user() now accepts an optional id parameter (default unchanged:
    "test-user-id", so every test that doesn't care about a specific id
    is untouched).
  - The three assignment-related tests now pass id=PROVIDER_USER_ID
    explicitly, so the fake user's id actually matches the fake
    provider_profiles row's user_id — the same way it would in a real
    Supabase project.
