Features implemented
--------------------
- Explicit, idempotent synthetic-only workflow seeding with no OpenAI call.
- Exact synthetic profile and active-assignment checks before every mutation.
- One completed run, three ordered agent actions, an approval indicator, and pending/
  in-progress tasks using the existing schema.
- Safe reset preview and explicit confirmation mode, with tasks/actions/runs deleted in
  foreign-key order and ordinary records excluded.
- Real provider API verification for sign-in, dashboard, assigned patient, patient detail,
  agent evidence, tasks, filtering, an allowed transition, authentication protection,
  invalid-transition protection, and forbidden-response-field checks.
- Sign-in 401 now shows "Invalid email or password." Authenticated 401 still clears the
  session and redirects with the session-expired message.
- Session helpers moved to a non-component module, removing all Fast Refresh warnings
  without suppressing the lint rule.
- Provider-review rendering assertion and new sign-in/session-expiry component tests.

Safety restrictions
-------------------
- Synthetic records are accepted only when both profiles contain the exact existing
  "(Synthetic Test Account)" marker and have an active assignment.
- The marker `synthetic-demo-no-openai` owns demo runs; reset selects only that marker.
- Demo actions use `synthetic_demo_evidence`; demo tasks use exact synthetic rationales.
- Scripts contain no credentials, user IDs, service-role values, access tokens, or API keys.
- Production API responses and React components contain no fabricated fallback data.
- No prompt, tool payload, raw response, diagnosis, or medication recommendation is seeded
  or exposed.
