THE BUG

  scripts/seed_synthetic_users.py crashed with:
    AttributeError: 'NoneType' object has no attribute 'data'
  immediately after successfully creating the provider Auth account,
  while checking whether a matching public.users row already existed.

ROOT CAUSE (confirmed by reading the actual installed library source,
not assumed):

  postgrest-py 0.16.11 (bundled with supabase-py 2.7.4) has this in
  SyncMaybeSingleRequestBuilder.execute():

      try:
          r = SyncSingleRequestBuilder.execute(self)
      except APIError as e:
          if e.details and "The result contains 0 rows" in e.details:
              return None

  .maybe_single().execute() returns a BARE None — not a response object
  with .data = None — when zero rows match. Every "does this row exist
  yet" check in the Phase 2 delivery assumed the latter and called
  .data directly, which crashes on the former. This affected every
  existence check across auth, patient/provider lookups, the check-in
  idempotency check, and the seed script — the seed script just hit it
  first because it's the first thing that runs against a real project.

THE FIX

  Every .maybe_single()/.single() call in the codebase is removed.
  Replaced with app/core/db.py's one_or_none(), which uses .limit(1)
  instead: .limit(1).execute() always returns a normal response object
  with .data as a list (empty or one item) — there is no special
  "zero rows behaves differently" case to get wrong.
