Features implemented
--------------------
- Replaced the provider dashboard's demo API calls with the authenticated FastAPI
  provider endpoints while retaining the existing view models, routing, MUI theme,
  pages and navigation structure.
- Added real provider sign-in through POST /auth/sign-in and reused the existing
  browser session/token mechanism for authenticated calls.
- Added strongly typed agent-run, agent-action and follow-up-task contracts.
- Added authenticated clients for:
  - GET /provider/patients/{patient_id}/agent-runs
  - GET /provider/follow-up-tasks (including optional status filter)
  - PATCH /provider/follow-up-tasks/{task_id}
- Added centralized, user-safe handling for 401, 403, 404, 409, 422 and network
  failures. A 401 clears the local session and triggers the existing sign-in flow.
- Added an AI Agent Workflow panel to patient details with status badges, timestamps,
  strict three-agent ordering, safe action summaries, approval/manual-review signals,
  and a truthful empty state.
- Uses neutral styling for skipped actions and avoids inferring whether a follow-up was
  created when a run requires manual review.
- Added an AI Follow-up Tasks navigation item and page with filtering, refresh,
  priority/status badges, patient name lookup, timestamps, loading/error/empty states,
  and valid state-transition actions.
- Task updates disable duplicate clicks, update immediately, refresh after success,
  show a concise success message, and refresh/explain 409 conflicts.
- No prompts, tool payloads, model payloads, internal error codes, Supabase service-role
  keys or OpenAI keys are rendered or stored by the frontend.
- No production fake agent data was added. Empty agent tables produce truthful empty
  states.

Manual demonstration
--------------------
1. Start FastAPI on http://127.0.0.1:8000 and Vite in a second terminal.
2. Open the Vite URL and choose the provider application.
3. Sign in with the synthetic provider account already created in Supabase Auth.
4. Open a patient record and review the AI Agent Workflow section.
5. If no agent run exists, confirm the truthful empty-state message is shown.
6. Open AI Follow-up Tasks from provider navigation.
7. Change the status filter and use Refresh.
8. For a pending task, select Start or Dismiss. For an in-progress task, select
   Complete or Dismiss. Confirm buttons disable while updating and the refreshed
   status appears after success.
9. Completed and dismissed tasks must remain read-only.
10. Sign out, or invalidate the token, and confirm protected requests return the user
    to provider sign-in without exposing backend details.
